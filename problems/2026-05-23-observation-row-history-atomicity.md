1. **Time & Date:** 2026-05-23T00:00:00Z
2. **Name:** Observation row and history.ndjson are not written atomically
3. **Issue:** Postgres observation row updates and object-gateway `history.ndjson` appends run in separate phases (row-first on CRUD and default ingest). A successful DB write can commit while history append fails, or history can exist while a follow-up DB write fails—breaking reconstructability and leaving row state ahead of the audit trail. Failure-mode tests for gateway partial failure are largely missing (~50% of the desired matrix).
4. **Severity:** S1 (Blocker)
5. **Location:** `atlas-core/services/functions/internal/function/observation.go`, `observation_ingest.go`, `observation_history_events.go`, `observation_history_reconcile.go`, `observation_history_dedup.go`; tests: `fixtures_test.go`, `observation_crud_test.go`, `observation_ingest_test.go`, `observation_history_test.go`
6. **Expected:** Event-backed fields (`identity`, `latest_telemetry`, lifecycle timestamps) on the row must not advance unless the matching append-only history line is durably recorded—or history-first writes must be idempotent with reconcile on any row failure after append. Retries converge without duplicate history events. Tests inject gateway failures (append after DB OK, DB after append OK) and assert row/history agreement.
7. **Actual:** `CreateObservation`, `UpdateObservation`, and `UpsertObservation` write Postgres then sync identity history. `executeIngestTelemetry` on existing rows does `UpdateObservation` then `appendTelemetryHistoryIfNeeded`. `reconcileAfterHistoryAppend` runs only on `ErrVersionConflict`, not generic DB errors. `fakeObjectGateway` has no per-op failure hooks; no test for DB succeeds + `history.ndjson` append fails.
8. **Reproduction:**

   2. Simulate `objectGateway.AppendFile` failure after a successful `UpdateObservation` on ingest (not yet covered by tests).
   3. Compare behavior to `docs/atlas-core/plans/observation-storage-redesign.md` append-then-row + reconcile guidance.
